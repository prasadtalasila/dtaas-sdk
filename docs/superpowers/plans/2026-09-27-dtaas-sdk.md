# dtaas-sdk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@into-cps-association/dtaas-sdk@0.1.0`, the contract package between the DTaaS host, the visualisation core and domain kits.

**Architecture:** One ESM package with four subpath entries (`.`, `./schema`, `./testing`, `./eslint`). Types for schema-backed data are inferred from zod schemas; the root entry imports them type-only. Testing utilities are jest-agnostic and depend on optional peers.

**Tech Stack:** Yarn 1.22.22, Node 24, TypeScript 6.0.3, tsup 8.5.1 + tsc-alias, Jest 30 + ts-jest 29 + jsdom, React 19, zod 4, @testing-library/react 16, react-router-dom 7, ESLint 9.39.5 (airbnb-base, react, react-hooks, prettier).

**Spec:** `docs/superpowers/specs/2026-09-27-dtaas-sdk-design.md`

## Global Constraints

- Package name `@into-cps-association/dtaas-sdk`, version `0.1.0`, `"type": "module"`, `"sideEffects": false`, licence `SEE LICENSE IN LICENSE.md`.
- `packageManager: yarn@1.22.22`, `engines.node: ">=24"`.
- Peers: `react >=19`, `zod ^4` required; `@testing-library/react >=16`, `react-router-dom >=7`, `eslint >=9` optional.
- Functions < 25 lines, files < 250 lines; interfaces over type aliases where possible; PascalCase components; camelCase utilities; `*.types.ts` / `*.schema.ts` suffixes; `globalThis` not `window`; single-export files use default export (airbnb `import/prefer-default-export`).
- Imports inside `src` use the `src/*` alias; tests use `src/*`, `tests/*`, `examples/*`.
- Tests live in `tests/unit`, `tests/integration`, `tests/e2e`; test files match `\.test\.tsx?$`.
- Coverage gate: lines/statements/functions 90 %, branches 85 %.
- `SDK_MAJOR = 1`; `STANDARD_SUBSTRATES = ['image','aec','mesh','video','embed','geo','field']`; `RESERVED_EXTENSION_IDS = ['config','library','digitaltwins','automation','account','workbench','preview','insights','ext','viz']`.

## Review Focus

1. Extension objects written in plain JS (no type checking) with missing arrays or wrong shapes — `validateExtension` must report errors, never throw. Test: pass `{}` and `null`-ish fields.
2. A route `element` that is an eager component (function) instead of `React.lazy` — must be rejected with a message naming the route path.
3. Env values with mixed-case ids and hyphens (`my-kit` → `REACT_APP_EXT_MY_KIT_`) — must map correctly and ignore other extensions' keys (e.g. `hello` must not pick up `REACT_APP_EXT_HELLO_WORLD_*` when `hello-world` exists? — prefix match is exact on `REACT_APP_EXT_HELLO_`; document that ids that are prefixes of other ids with `-` can collide, and `validateExtension` cannot see across kits). Test: unrelated keys ignored.
4. `valueAt` with `t` before the first sample, with no samples, and with out-of-order emission — returns `undefined`, `undefined`, and the latest-at-or-before respectively.
5. A kit page that throws during render or whose lazy import rejects — `checkConformance` must report the error, not crash the test run.
